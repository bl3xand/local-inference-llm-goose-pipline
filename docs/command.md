# Шпаргалка: локальные модели и Goose

Правило для всех команд удаления: без `--yes` команда только показывает, что удалила бы. С `--yes` удаляет.

## Репозиторий и настройки

Всё самописное лежит в `/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/`. Файлы в домашней папке — копии оттуда.

Числа, которые подбираем (запас видеопамяти, окно, потоки, размер картинки, порог сжатия), лежат в одном файле:

```bash
xdg-open /mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/.env
```

Применить после правки `.env` или любого файла репозитория (новое подхватится при следующем открытии Goose):

```bash
/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/install.sh
```

То же и сразу перезапустить сервер (оборвёт идущий чат):

```bash
/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/install.sh --restart
```

Отправить изменения на GitHub:

```bash
cd /mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline && git add -A && git commit -m "настройки" && git push
```

Править надо файлы в репозитории, а не копии в `~/.config`: следующий `install.sh` вернёт копии к виду из репозитория.

## Правила для моделей

Файл правил, общий для всех моделей и всех папок:

```
/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/goose/.goosehints
```

После правки выполнить `install.sh` (см. выше): он положит копию в `~/.config/goose/.goosehints`, откуда её читает Goose.

Посмотреть:

```bash
cat /mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/goose/.goosehints
```

Открыть в редакторе:

```bash
xdg-open /mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/goose/.goosehints
```

Изменения действуют в новых чатах: уже открытый чат читает правила при старте.

Правила только для одного проекта кладутся в файл `.goosehints` в папке этого проекта (в окне: Настройки → Чат → «Подсказки проекта»). Они добавляются к общим, а при противоречии побеждают.

Соседние файлы, которые ссылаются на правила:

| Что | Файл |
|---|---|
| Первая строка системной подсказки | `~/.config/goose/prompts/system.md` |
| Напоминание в каждом ходе | `~/.config/environment.d/goose.conf` |
| Что сохранять при сжатии контекста | `~/.config/goose/prompts/compaction.md` |
| Текст после сжатия | `~/.config/goose/prompts/compaction_summary.md` |
| Подсказка субагентов | `~/.config/goose/prompts/subagent_system.md` |

## Новая модель

1. Положить `.gguf` и её блок зрения `mmproj-….gguf` в `~/Документы/LLM/models/`.
2. Перезапустить Goose через ярлык. Модель появится в списке сама.

Показать таблицу «файл → имя в Goose», ничего не меняя:

```bash
python3 ~/Документы/LLM/vision-all.py
```

Применить вручную (после добавления или удаления модели):

```bash
python3 ~/Документы/LLM/vision-all.py --apply
```

То же и сразу перезапустить сервер (оборвёт идущий чат):

```bash
python3 ~/Документы/LLM/vision-all.py --apply --restart
```

Обновить каталог облачных моделей Goose и вернуть в него наши:

```bash
python3 ~/Документы/LLM/vision-all.py --update-catalog
```

Убрать наши записи из каталога:

```bash
python3 ~/Документы/LLM/vision-all.py --undo
```

## Память

Показать всё по разделам, с размером и возрастом:

```bash
goose-memory show
```

Стереть один раздел (вместо `chats` — имя папки проекта):

```bash
goose-memory clear chats --yes
```

Стереть раздел общих правил:

```bash
goose-memory clear general --yes
```

Стереть разделы, в которые не писали три месяца (можно `90d`, `1y`):

```bash
goose-memory forget 3m --yes
```

Стереть всю память:

```bash
goose-memory clear-all --yes
```

## История чатов

Пронумерованный список последних 30 чатов:

```bash
goose-forget list
```

Список подлиннее:

```bash
goose-forget list 100
```

Удалить чаты по номерам из списка:

```bash
goose-forget pick 1 3 5-9 --yes
```

Удалить все чаты одной папки (имя папки или полный путь):

```bash
goose-forget project chats --yes
```

Удалить чаты, которыми не пользовались три месяца:

```bash
goose-forget 3m --yes
```

Удалить вообще все чаты:

```bash
goose-forget all --yes
```

## Полная очистка перед новым прогоном

Чаты и память разом:

```bash
goose-forget all --yes && goose-memory clear-all --yes
```

## Сервер с моделями

Обычно им управляет ярлык Goose: открыли — запустился, закрыли — остановился.

```bash
systemctl --user status llama-server
```

```bash
systemctl --user restart llama-server
```

```bash
systemctl --user stop llama-server
```

Перезапуск нужен после изменения настроек моделей. Он обрывает текущий ход, после него в чате надо написать «продолжай».

## Что происходит прямо сейчас

Скорость и счётчик токенов текущего ответа — видно, думает модель или стоит:

```bash
journalctl --user -u llama-server -f -o cat | grep --line-buffered -E "n_gen|eval time"
```

Память вживую, раз в 2 секунды: видеопамять, память драйвера карты, свободная оперативная (Ctrl+C — стоп):

```bash
/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/tools/memwatch.sh
```

То же с предохранителем: выгрузить модель, если свободной оперативной меньше 6000 МиБ:

```bash
/mnt/myfiles/Development/Linux/local-inference-llm-goose-pipline/tools/memwatch.sh --guard 6000
```

Не убила ли система сервер из-за нехватки памяти:

```bash
journalctl -k --since "-30 min" | grep -i "out of memory"
```

Сколько оперативной памяти занято:

```bash
free -g
```

## Если в чате что-то не так

| Признак | Что делать |
|---|---|
| Жёлтая строка `Failed to start extension 'websearch'` в начале чата | поиска в этом чате не будет: закрыть и открыть новый |
| В ответе `image omitted` | `vision-all.py --apply`, перезапустить Goose |
| Модель молчит дольше трёх минут | посмотреть счётчик токенов (команда выше); если растёт без конца — «стоп» и «продолжай» |
| Модель остановилась, не закончив | написать «продолжай» |
| Модель просит вас выполнить команду | напомнить: «у тебя есть shell, выполни сама» |
